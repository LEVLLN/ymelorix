# Регулярная выгрузка по расписанию (cron)

← [README](../README.md)

`--update` плюс cron превращают загрузчик в синхронизатор: раз в сутки он дозакачивает то, что
появилось в избранном, и не трогает остальное. **Без `--update` в cron ставить нельзя** — каждую
ночь заново выкачивался бы весь список.

## 1. Токен — в отдельный файл

В строке crontab токену не место: crontab попадает в резервные копии и читается целиком любым,
кто получил доступ к учётной записи. Отдельный файл с правами `600` ограничивает утечку одним
файлом, который легко найти и заменить.

```sh
sudo install -m 600 -o root -g root /dev/null /etc/ymelorix.env
sudoedit /etc/ymelorix.env      # одна строка: YANDEX_TOKEN=y0_AgAAAA...
```

Не вписывайте токен командой вида `echo ... > файл` — он останется в истории оболочки.

Где взять сам токен — в [отдельном документе](token.md).

## 2. Скрипт-обёртка

```sh
#!/bin/sh
# /usr/local/bin/sync-music.sh, chmod 755
set -eu

. /etc/ymelorix.env
export YANDEX_TOKEN
export RUST_LOG=ymelorix=warn

exec /usr/local/bin/ymelorix download-favorites \
    --path /srv/music \
    --update
```

Обёртка, а не одна строка в crontab, по трём причинам. У cron скудное окружение: `PATH` обычно
`/usr/bin:/bin`, профиль не читается, поэтому все пути обязаны быть абсолютными. Знак `%` в
crontab означает перевод строки, и любая команда с процентом там ломается. И `RUST_LOG` по
умолчанию — `ymelorix=trace`, то есть в лог поедет JSON на каждый шаг; для расписания
достаточно `warn`.

`export YANDEX_TOKEN` после `.` обязателен: точка выполняет присваивание, но не экспортирует
переменную, а дочернему процессу нужно именно окружение.

## 3. Строка crontab

```cron
17 4 * * * /usr/bin/flock -n /var/lock/ymelorix.lock /usr/local/bin/sync-music.sh >> /var/log/ymelorix.log 2>&1
```

Что здесь зачем:

- **`17 4`, а не `0 4`** — в круглый час просыпаются задания всего мира, и API это чувствует.
- **`flock -n`** — два одновременных прогона в одну директорию мешают друг другу: они делят
  временные файлы `*.part`. Флаг `-n` означает «не ждать»: если прошлый прогон ещё идёт,
  сегодняшний просто не запустится.
- **`>> … 2>&1`** — ход работы печатается в stderr, а cron шлёт письмо на любой вывод. Без
  перенаправления вы получите письмо после каждой удачной ночи и перестанете их читать.

Логи растут — заведите на них `logrotate`.

## Как узнавать о сбоях

Команда возвращает `0`, только если каждый трек скачан или пропущен; при любой неудаче — код
ошибки и объяснение в логе. Если письма нужны только о сбоях, поставьте `moreutils` и заверните
вызов в `chronic` — он молчит при нулевом коде возврата и печатает всё при ненулевом:

```cron
17 4 * * * /usr/bin/chronic /usr/bin/flock -n /var/lock/ymelorix.lock /usr/local/bin/sync-music.sh
```

Не оборачивайте выгрузку в бесконечные повторы: недоступный трек не станет доступнее, а пять
неудач подряд команда и так считает поводом остановиться. Что именно обрывает выгрузку —
в разделе [«Поведение при сбоях»](../README.md#поведение-при-сбоях).

## Что сломается со временем

- **Токен протухнет.** Выданные Яндексом OAuth-токены живут около года, и однажды ночная
  выгрузка упрётся в `401`. Лечится [перевыпуском токена](token.md).
- **Кончится место.** Выгрузка прервётся сразу, а не после трёхсот одинаковых неудач.
- **На systemd** таймер обычно удобнее: `journalctl -u` вместо файла лога, `Persistent=true`
  вместо пропущенного запуска на выключенной машине.
